# Семейства Linux: Debian, Red Hat, Arch — родословная

## 1. Что такое «семейство» дистрибутивов

Linux — это только **ядро**. Всё остальное (утилиты GNU, init-система, менеджер пакетов, репозитории, политика обновлений) собирает дистрибутив. Дистрибутивы, которые происходят друг от друга или используют общий формат пакетов и общие инструменты, образуют **семейство**.

Что обычно объединяет семейство:

- **формат пакетов** (`.deb`, `.rpm`, `pkg.tar.zst`);
- **менеджер пакетов** (`apt`, `dnf`, `pacman`);
- **философия релизов** (стабильные релизы или rolling);
- **расположение конфигов и соглашения** (часть различий мелкая, но важная для администратора).

Три крупнейших семейства: **Debian**, **Red Hat** и **Arch**. Есть и другие корни (Slackware, Gentoo, SUSE, Alpine), но эти три покрывают основную часть серверов, десктопов и обучающих материалов.

## 3. Семейство Debian

### История
- Основан **Ианом Мёрдоком** в **1993** году как полностью «общественный» дистрибутив.
- Управляется сообществом, а не компанией. Основа — **Debian Social Contract** и **Debian Free Software Guidelines**.
- Выпускает версии с кодовыми именами из «Истории игрушек» (bookworm, trixie и т. д.).

### Технические особенности
| Параметр | Значение |
|---|---|
| Формат пакетов | `.deb` |
| Низкоуровневый инструмент | `dpkg` |
| Высокоуровневый менеджер | `apt` (`apt-get`, `aptitude`) |
| Ветки репозиториев | `stable`, `testing`, `unstable (sid)` |
| Модель | стабильные релизы, обновления только безопасности и критичные исправления |
| Конфиги | `/etc/apt/sources.list`, `/etc/apt/sources.list.d/` |

### Потомки
- **Ubuntu** (2004, Canonical) — самый популярный потомок. Релизы каждые 6 месяцев, **LTS** раз в 2 года (поддержка 5 лет, дольше по платной подписке). Основа большинства облачных образов и туториалов.
- **Linux Mint** — десктоп для тех, кто хочет «поставил и работает».
- **Kali Linux** — инструменты для тестирования на проникновение.
- **Raspberry Pi OS** — для Raspberry Pi.
- **Pop!_OS**, **elementary OS**, **MX Linux**, **Devuan** (Debian без systemd).

### Сильные стороны
- огромные репозитории;
- предсказуемость и стабильность;
- лучшая документация и количество готовых инструкций (особенно для Ubuntu);
- де-факто стандарт для VPS, Docker-образов (`debian`, `ubuntu`) и CI.

### Слабые стороны
- пакеты в `stable` заметно «старше» upstream;
- для свежих версий ПО приходится подключать сторонние репозитории, backports, snap или контейнеры.

## 4. Семейство Red Hat

### История
- **1995** — выходит **Red Hat Linux**, первый коммерчески успешный дистрибутив.
- **2003** — Red Hat разделяет продукт: бесплатный **Fedora** (быстрые релизы, экспериментальная площадка) и коммерческий **Red Hat Enterprise Linux (RHEL)** с платной поддержкой.
- **2004** — появляется **CentOS**, бесплатная пересборка исходников RHEL.
- **2019–2020** — CentOS переходит на **CentOS Stream** (ветка перед RHEL), а классический CentOS Linux закрывают.
- **2021** — появляются **Rocky Linux** (создатель CentOS Грегори Курцер) и **AlmaLinux** как заменители.
- **2023** — Red Hat ограничивает публичный доступ к исходникам RHEL; сообщество и вендоры отвечают собственными инициативами (в том числе AlmaLinux меняет подход к совместимости).

### Цепочка разработки
```
Fedora  ──►  CentOS Stream  ──►  RHEL  ──►  Rocky / AlmaLinux / Oracle Linux
(новое)       (предрелиз)       (релиз)      (клоны для бесплатного использования)
```

### Технические особенности
| Параметр | Значение |
|---|---|
| Формат пакетов | `.rpm` |
| Низкоуровневый инструмент | `rpm` |
| Высокоуровневый менеджер | `dnf` (ранее `yum`) |
| Модель | стабильные мажорные релизы, поддержка 10 лет |
| Безопасность | **SELinux** включён по умолчанию |
| Сетевой фаервол | `firewalld` |
| Конфиги репозиториев | `/etc/yum.repos.d/` |

### Сильные стороны
- корпоративный стандарт: банки, телеком, крупные дата-центры;
- долгая поддержка и предсказуемый жизненный цикл;
- сильная экосистема безопасности (SELinux, сертификации);
- востребованность на рынке труда (RHCSA/RHCE).

### Слабые стороны
- консервативные версии пакетов;
- SELinux требует отдельного изучения;
- коммерческая политика Red Hat периодически вызывает споры в сообществе.

> Рядом стоит **SUSE / openSUSE**: тоже использует `.rpm`, но менеджер пакетов `zypper` и инструмент `YaST`, а родословная идёт от Slackware. Это отдельное семейство, но на практике RPM-мир его часто объединяет с Red Hat.

## 5. Семейство Arch

### История
- **2002** — Джадд Винет создаёт Arch Linux под влиянием идей CRUX. Принцип — **KISS** (Keep It Simple): простота с точки зрения устройства системы, а не удобства установки.
- Дистрибутив **rolling release**: нет «версий», система обновляется непрерывно.

### Технические особенности
| Параметр | Значение |
|---|---|
| Формат пакетов | `.pkg.tar.zst` |
| Менеджер пакетов | `pacman` |
| Сборка пакетов | `PKGBUILD` + `makepkg` |
| Пользовательские пакеты | **AUR** (Arch User Repository) |
| Модель | rolling release |
| Установка | вручную (`pacstrap`, `arch-chroot`), либо через `archinstall` |
| Документация | **Arch Wiki** — одна из лучших в мире Linux |

### Потомки и производные
- **Manjaro** — удобнее для новичков, но имеет собственные репозитории с задержкой.
- **EndeavourOS** — ближе к «чистому» Arch с графическим установщиком.
- **Garuda**, **CachyOS** — упор на производительность и десктоп.
- **SteamOS 3** — Steam Deck.

### Сильные стороны
- самые свежие версии ПО;
- полный контроль над системой, ты сам собираешь то, что нужно;
- отличное обучение: после установки Arch понимаешь загрузку, разметку, fstab, initramfs, bootloader;
- Arch Wiki полезна и пользователям других дистрибутивов.

### Слабые стороны
- обновления могут ломать систему, нужно читать новости перед `pacman -Syu`;
- редко используется на продакшн-серверах;
- вход выше, чем у Ubuntu.

## 6. Сравнительная таблица

| | **Debian-семейство** | **Red Hat-семейство** | **Arch-семейство** |
|---|---|---|---|
| Основан | 1993 | 1995 | 2002 |
| Пакеты | `.deb` | `.rpm` | `.pkg.tar.zst` |
| Менеджер | `apt` | `dnf` | `pacman` |
| Модель релизов | стабильные | стабильные, 10 лет поддержки | rolling |
| Свежесть ПО | умеренная / низкая | низкая (RHEL) | максимальная |
| Типичная среда | VPS, облако, Docker, десктоп | корпорации, enterprise | десктоп, обучение, энтузиасты |

| Порог входа | низкий | средний | высокий |
| Лучшая документация | Ubuntu Help, Debian Wiki | Red Hat Docs | Arch Wiki |

## 7. Шпаргалка: одно и то же в разных семействах

| Действие | Debian / Ubuntu | RHEL / Fedora / Rocky | Arch |
|---|---|---|---|
| Обновить список пакетов | `apt update` | `dnf check-update` | `pacman -Sy` |
| Обновить систему | `apt upgrade` | `dnf upgrade` | `pacman -Syu` |
| Установить пакет | `apt install nginx` | `dnf install nginx` | `pacman -S nginx` |
| Удалить пакет | `apt remove nginx` | `dnf remove nginx` | `pacman -R nginx` |
| Найти пакет | `apt search nginx` | `dnf search nginx` | `pacman -Ss nginx` |
| Информация о пакете | `apt show nginx` | `dnf info nginx` | `pacman -Si nginx` |
| Какой пакет владеет файлом | `dpkg -S /path` | `rpm -qf /path` | `pacman -Qo /path` |
| Список установленных | `dpkg -l` | `rpm -qa` | `pacman -Q` |
| Установить локальный файл | `dpkg -i x.deb` | `rpm -i x.rpm` | `pacman -U x.pkg.tar.zst` |

## 8. Что выбрать под свои цели

Для маршрута **backend + DevOps**:

1. **Debian / Ubuntu Server** — основа. Большинство VPS, Docker-образов, туториалов и CI-окружений.
2. **Rocky / AlmaLinux** — знать обязательно: корпоративный мир, SELinux, `firewalld`, `dnf`.
3. **Arch** — по желанию, как учебный полигон: ставишь руками и понимаешь, как устроена система.

Практический вывод: **основной навык — Linux как таковой**, а не конкретный дистрибутив. Различия между семействами в основном в пакетах, политике релизов и мелких соглашениях.

## 9. Практика для закрепления

1. Поднять три виртуальные машины (VirtualBox, KVM или контейнеры): Debian, Rocky и Arch.
2. На каждой: установить `nginx`, запустить через `systemctl`, открыть порт в фаерволе (`ufw` / `firewalld`).
3. Найти, в каком пакете лежит `/usr/bin/curl`, на каждой системе.
4. Посмотреть, где хранятся репозитории и как добавить сторонний.
5. На Rocky проверить `getenforce` и разобраться, что такое SELinux-контекст.
6. Написать таблицу «одинаковые задачи — разные команды» своими руками.
